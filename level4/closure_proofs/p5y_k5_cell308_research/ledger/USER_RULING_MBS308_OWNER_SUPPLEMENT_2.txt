1. OFFICIAL-QUALIFICATION MEMORY-WATCHDOG EVENT
======================================================================

I resolve the conflict prospectively as follows.

For the DESIGNATED PRE-FREEZE measurement/derivation stage, preserve the
already-ratified R-MEM rule:

    if the provisional 3-GiB run has a memory-watchdog event,
    it is not a valid input and the rule calls for the specified
    6-GiB re-run, subject to the already-ratified step-5 memory bound.

Do not change that pre-freeze rule.

However, once the canonical R-rule outputs have been derived and the SINGLE
MB-S freeze has been created, the role of official qualification is
validation of the frozen operational object, not re-derivation by changing
that object.

Therefore:

    if ANY official-qualification decoy triggers the memory watchdog
    while running under the ACTUAL FROZEN MEM_CAP,

the official qualification shall:

    FAIL CLOSED.

    QUALIFICATION_MEMORY_WATCHDOG_UNDER_FROZEN_CAP

or the nearest existing reviewed naming convention.

Do NOT run the official decoy at 2x the frozen MEM_CAP.

Do NOT mutate MEM_CAP after freeze.

Do NOT create a qualification-only memory cap.

Do NOT treat another clean run for the same cell as curing the event.

Do NOT proceed to grant or target execution after this failure.

Preserve the failed qualification evidence and stop before target.

This is an explicit MB-S sequencing resolution of the conflict between the
historical R-MEM derivation re-run rule and the single-freeze option-(a)
qualification semantics.

The distinction is:

    PRE-FREEZE DESIGNATED MEASUREMENT:
        derives the operational constant;
        the already-ratified provisional-cap re-run rule remains applicable.

    POST-FREEZE OFFICIAL QUALIFICATION:
        validates the frozen operational constant;
        a watchdog event under that frozen constant is a qualification
        failure and cannot change the constant.
