## A. What the previous P6R2 implementation got wrong

P6R2 removed policy-dependent RNG **seeds** — the tape for cycle `j` was keyed on
`(cell, j)` only — and that part was sound. Two things were not.

1. **Overflow was drawn from a shared sequential generator indexed by the live
   set.** Once a cycle ran past the 2,000-step pre-generated tape:

   ```python
   x = overflow.standard_normal(idx.size)     # idx = the CURRENT LIVE SET
   ```

   The number of values pulled, and therefore which value reached which
   replicate, depended on how many replicates were still running — which depends
   on the policy parameter. `cusum_m5` overflow counts differed materially across
   variants.

2. **The identity claim was inferred from cycle 0 alone.** Only cycle-0
   innovations were compared, and `all_paths_identical_across_variants = true`
   was written from that check. Later entering states, `zbar`/stopping paths and
   live sets did differ — as they must — so the flag was both unsupported and
   describing the wrong property.

## B. Why "same seed" is not "same primitive path" under state-dependent consumption

A sequential generator delivers its `n`-th value to the `n`-th *request*. When
requests are issued per live replicate, the request count is a function of the
endogenous state, so the same seed maps different values to the same replicate
once any variant's stopping behaviour changes. Seed equality only fixes the
*sequence*; it does not fix the *assignment of sequence positions to
(replicate, cycle, observation index)*.

The property actually required is **addressability**, not shared sequential
consumption.

## C. How addressable per-replicate/per-cycle primitives fix it

Every draw is now a pure function of its address:

```text
(SEED_NAMESPACE, detector, m, k, replicate_id, cycle_id,
 primitive_type, primitive_index)  ->  float64
```

The address contains **no** `policy_id`, no sensitivity variant, no `s1`
multiplier, no live-set position, no stopping time, no branch order and no count
of previously consumed draws. Four independently addressable primitive types are
provided: `monitor`, `fresh`, `init`, `aux`.

Values are materialised in **blocks of `BLOCK_LEN = 512`** observations, one
block per `(cell, cycle, primitive_type, block_index)`, generated by a
counter-based **Philox** stream keyed only on that address. Observation `t` lives
at block `t // 512`, offset `t % 512`, row `r` — **for every `t`, forever**.
Block `b` is generated independently of whether block `b-1` ever existed, so
**overflow is not a special case**: `t = 2457` is served exactly as `t = 3` is.
`BLOCK_LEN` is deliberately small so overflow past the first block is routine in
the ordinary experiment rather than reachable only by a contrived test — the
runs below touched block indices up to **10** (`t > 5,000`).

The simulator reads the **full column** for all `n_rep` replicates at address
`(cycle, t)` and selects the live ones by boolean mask. A replicate's value
cannot depend on how many others are active. **This is the whole repair.**

Endogenous trajectories are left free. They diverge, they are measured, and
their divergence is reported rather than suppressed.

> All sensitivity variants consume the same addressable exogenous primitive
> random field; endogenous trajectories may diverge as a consequence of the
> parameter perturbation.

**Where `s1` cannot fire, and why.** In four cells (`cusum_m1`, `cusum_m2`,
`sr_m1`, `sr_m2`) **no cycle had `tau < m`**, so the truncated-window branch that
`s1` governs was never taken. The perturbation is inert **by construction, not by
accident**, and the movement is exactly `0.000%` — which is what a correct CRN
design must produce and what the confounded artifact could not. Note `cusum_m2`
and `sr_m3` have 3 and 20 observations behind `s1` in the *calibration* record
but 0 and 3 firing cycles in *this* experiment; the `s1` estimate there rests on
almost nothing either way.

Where `s1` can fire, the movement is small but genuinely non-zero and now
attributable: the largest effect is `+0.341%` of mean `rho` at `cusum_m5` under
`s1 := s0`, and the direction is consistent (raising `s1` lowers `rho` on
truncated cycles, lowering it raises `rho`). **The corrected numbers are smaller
than the confounded ones because the confound was Monte Carlo path noise, not
because anything was tuned.** Had they been larger they would have been reported
as larger.

## F. Remaining calibration limitations

Unchanged, carried forward from the frozen calibration record and **not**
reinterpreted:

* **6/8 cells converged**; **`cusum_m2` did not**; **`sr_m3` did not**;
* **sparse `s1` evidence**: 0, 3, 20 observations behind `s1` at
  `cusum_m1`/`sr_m1`/`sr_m2`, `cusum_m2`, `sr_m3`;
* **fallback cells exist**: `cusum_m1`, `sr_m1`, `sr_m2` have `s1 := s0` because
  no truncated window was ever observed during calibration;
* the **final large-pass refit is not a verified fixed point**;
* the `1e-2` variance floor is inactive everywhere and `rho_max` cannot bind;
* **this experiment does not prove calibration convergence.** It measures only
  the empirical sensitivity of aggregate outcomes to the declared `s1`
  perturbations under shared exogenous randomness.

No calibration quality claim is upgraded.

## Note on the anchor-to-result iteration

Two defects in P6R2b's **own** modules were found and fixed between the
pre-repair anchor (`43c9470`) and the result checkpoint, **before any result was
generated**: the `init` primitive used a negative cycle index that
`SeedSequence` rejects, and the exhaustive field hash was computationally
infeasible and was replaced by a declared **sampled** field digest
(offsets `{0, 1, 255, 511}` within each monitor block, exhaustive over every
cycle and block index touched). Both are inside the P6R2b namespace; no
historical artifact was involved.
