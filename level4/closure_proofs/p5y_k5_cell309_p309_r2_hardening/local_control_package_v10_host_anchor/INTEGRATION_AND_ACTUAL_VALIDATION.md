# Broker connection, installation, actual validation and recovery

The accepted lifecycle and ACCESS_AND_RECOVERY remain the authority. This library adds no D2 public start, freeze/grant, automatic generation or formal retry. The proposed Windows Controller/VMRuntime and guest root handshake must be reviewed and installed as a separate concrete package.

Required connection order:

1. Independently enroll the pinned host ACK public key and guest root proof key via the approved image/bootstrap ceremony. Never adopt keys from a first hello. Verify the selected new guest/seed/runtime/monitor/source/policy and permitID/approval/checkpoint before mutation.
2. The real VmRuntime factory owns the fixed QEMU Job/process, creation time/token/image/enrollment/seed identity and authenticated guest root channel. Root guest creates its one-use local pre-start fence and G/challenge, then signs the pre-start purpose. A host service must verify all of this and independent root pin before constructing the opaque lease. Synthetic leases are compiled out of the production DLL.
3. Controller opens the fixed installed anchor with that lease, creates its immutable first claim, then ReserveOnce consumes the same prospective permit. File flush/readback and final latch CAS precede any reserve ACK. The controller signer produces a single session context and reserve ACK. The authenticated fixed H2 route delivers those two packets once, in order. No reserve ACK means no OS worker start.
4. Guest starts only the fixed blocked gate transaction and obtains real manager invocation identities plus guardian READY. It signs the blocked purpose. Host independently checks that exact proof against current held VM/channel/reservation and only then BindOnce records the same permit's instances. It signs one final ACK. No final ACK means no gate release. This is not a second run or G.
5. Guest independently verifies context/pins/local expected fields/challenge/record and exact final purpose before its one attempt to release the already-owned fixed gate. Independently supervised guest and host stop paths must remain live during blocked storage, CNG, manager calls, channel loss and late completion. A valid signature by itself never renews continuation or says cleanup finished.

The future fixed Controller↔VmRuntime/Observer endpoints need native first-instance collision detection and PIPE_REJECT_REMOTE_CLIENTS. Client masks must explicitly exclude FILE_CREATE_PIPE_INSTANCE (0x4); an illustrative data-client mask is FILE_READ_DATA|FILE_WRITE_DATA|FILE_READ_ATTRIBUTES|SYNCHRONIZE = 0x00100083, subject to actual endpoint requirements. Generic write must not be used as shorthand. Authenticate local SCM-held service process, primary TokenUser, creation time, image and enrollment; message PID/SID/G/VM fields are comparisons, not authoritative identities. No relay/guest receives anchor, key, manager, service token or Job handle. The library implements no pipe and makes no transport-authentication claim.

Required actual evidence before installation/validation can pass:

- Exact object collisions for every proposed service/account/root/pipe/Job/key, including the separately proposed fourth VmRuntime service, which the saved v6 three-service checks never queried. Do not infer absent key/pipe/Job from absent directories/services.
- Actual OWN_PROCESS Controller virtual account, ServiceSidType RESTRICTED, enabled/restricted SID, no impersonation, fixed image, exact RequiredPrivileges and actual token allowlist. Anchor requires only SeChangeNotifyPrivilege; token/LSA direct not-found is not evidence that the future service token satisfies it. Observer collector privileges need their own real proof, not a LocalSystem/SeDebug fallback.
- Admin/SYSTEM-owned protected code/config roots; no service write to pinned code/enrollment. Separate protected Controller anchor root and separately owned Observer checkpoint/key. Verify each ancestor and child, no reparse/hard links, object IDs, NTFS, and exact negative access tests under operator/relay/guest/other service tokens. Directory share-write is compatible with the rename implementation and does not by itself protect ACLs or metadata.
- Existing ACK key provider/name/MachineKey/Signing-only/None-export properties, actual key owner/DACL, unique identity and independently enrolled SPKI pin; Controller ACK and Observer facts keys remain separate. No provider-private filesystem copying or guessed ACL masks substitutes for CNG checks. This package created/opened no real key.
- Actual guest-root bootstrap challenge authentication and independent pin ceremony; fixed canonical proof verification; real held VM/Job/process lifetime and channel peer checks; no TOFU or caller-set DTO. Actual proof of the current guest boot and manager/guardian invocation identities is still absent here.
- Real controller stop independent of journal/CNG, held Job termination after VMRuntime death, guardian stop on missing host/liveness/channel, no late RUNNING/start/release ACK, exact cleanup/reap/empty/cgroup/no-inflight proof, cold-start refusal, guest rollback with old G/seq/proof, host reboot/power-loss behavior and uncertainty retention. Temp tests prove only library file/concurrency behavior.

Saved v6 facts constrain the installer: CBSRebootPending was true and was not cleared; selected hibernate idle AC=0 is not a proven 'never'. Effective API descriptor for the private GUID was a default although both registry-name forms were absent; its bytes must not be fabricated as an original registry backup. D: root/existing record ancestry was ordinary-user writable; actual custody of a proposed new protected child remains unverified. Neither saved D: records nor this user's temp fixtures are a production anti-rollback anchor. Original 0.4392592 seconds of unknown CPU attribution is unchanged by this work. No I1–I7 item is closed.

Recovery/rollback starts by revoking future start and calling the independent irreversible stop latch/owned-instance stop. Keep broker/controller/guardian identity tracking alive until exact owned cleanup is proven; do not dismantle the only stop path first. Preserve claimed/partial/unknown journal, enrollment, checkpoint, keys/pins and failed evidence. Missing/corrupt/uncertain state is quarantine/RECOVERY_UNKNOWN, not an invitation to recreate ENROLLED, decrement sequence, reuse G, replay ACK or retry release. Restore only exact installer changes from recorded originals, and remove new service/unit/identity code only after no in-flight/owned work remains. Do not automatically clear CBS, relax unrelated ACLs, unregister/delete a distribution/VHDX, remove original Ubuntu/runtime/data, or turn host-change rollback into formal run retry authority.
