# Primary API basis, checked 2026-10-16

- [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew): CREATE_NEW refuses an existing object; share zero excludes subsequent read/write/delete opens; handles are non-inheritable when SECURITY_ATTRIBUTES is null. WRITE_THROUGH flushes cached writes without delay; NTFS also flushes affected metadata, but hardware may not support write-through. Sharing is not a substitute for ACL custody and does not prohibit every attribute operation.
- [FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers): file GENERIC_WRITE is required; success writes buffered file information to the device. Volume flush needs administrator privilege and is not used. This does not independently certify a physical device's power-loss behavior.
- [Directory Handles](https://learn.microsoft.com/en-us/windows/win32/fileio/obtaining-a-handle-to-a-directory): BACKUP_SEMANTICS opens a directory; the documented directory-handle function list is not a portable fsync(dir) contract. No directory-flush success is invented in this implementation.
- [FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info), [SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle), [official SDK header](https://raw.githubusercontent.com/microsoft/win32metadata/main/generation/WinSDK/RecompiledIdlHeaders/um/WinBase.h): source DELETE access and no-replace behavior are explicit. The implementation uses a null-terminated UTF16 destination, correct x64 header alignment, no-replace flag, file flush and same-handle final-path/readback. This is one native namespace operation, not a database/power-loss transaction theorem. The mutable SDK URL is a layout reference, not an execution pin.
- [GetSecurityInfo](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-getsecurityinfo), [file rights](https://learn.microsoft.com/en-us/windows/win32/fileio/file-access-rights-constants): held-handle descriptor reads require READ_CONTROL; return memory uses LocalFree. Protected inheritance alone does not imply secure effective grants. Root and ancestors require distinct mutation/child-creation checks; unsupported ACE forms are refused.
- [SERVICE_SID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/ns-winsvc-service_sid_info), [QueryServiceStatusEx](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-queryservicestatusex), [TOKEN_USER](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-token_user), [OpenThreadToken](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-openthreadtoken): TokenUser, enabled group SID, restricted SID, service configuration and current owned process are different facts. Pending-state service PID is not accepted. OpenAsSelf does not remove impersonation.
- [SERVICE_REQUIRED_PRIVILEGES_INFOW](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/ns-winsvc-service_required_privileges_infow): SCM RequiredPrivileges is a MULTI_SZ service configuration. The current factory requires exactly SeChangeNotifyPrivilege there and in the actual token, not a six-item deny list. Installation and actual token behavior remain untested.
- [NCryptOpenKey](https://learn.microsoft.com/en-us/windows/win32/api/ncrypt/nf-ncrypt-ncryptopenkey), [key storage properties](https://learn.microsoft.com/en-us/windows/win32/seccng/key-storage-property-identifiers): MachineKey identifies machine scope; usage/export/security descriptor/unique-name properties have distinct meanings. The source uses only opening and public-key export; no key creation/import/private export/ACL mutation is present. Protected DACL and exact pin checks are additional application policy, not evidence already obtained from a real key.
