# Saved ExtendedData aggregation v8

The approved task is a source-built Windows offline consumer for the one supplied saved ETL. This package contains implementation and synthetic memory checks. It does not authorize or perform an actual ETL scan, a new capture, or a host query. All I1–I7 remain OPEN and admission remains BLOCKED.

The selected approach uses the Windows SDK `EVENT_RECORD` callback directly. A managed marshalling wrapper would add an ABI surface without helping this narrow aggregate, while reusing a larger decoder would introduce payload and identity reconstruction behavior that this task does not need. The implementation therefore has one C++ translation unit and a separate ordinary build runner.

`--self-test` constructs small in-memory `EVENT_RECORD` objects. It opens no ETL and invokes no `OpenTrace`, `ProcessTrace`, or trace controller API. `--scan-saved <fresh-attempt-name>` is a separately reviewed future entry point. It accepts no input path, key value, decoder selection, session name, or real-time option. The input path, expected SHA256, and expected byte length are fixed in the source.

The future saved-file path holds each input ancestor without delete sharing, rejects reparse points, and holds the leaf without write or delete sharing. It hashes that same leaf handle before and after `ProcessTrace`, verifies the fixed size and file identity, and records every explicit close result. `OpenTrace` receives the fixed path while these pins remain held. The mode is `EVENT_RECORD | RAW_TIMESTAMP`, and a non-QPC clock or invalid QPC frequency produces a partial result rather than a clock conversion guess.

Every delivered record contributes to a provider / event ID / version / opcode bucket. Every inspectable ExtendedData descriptor contributes to an ExtType / DataSize row within that bucket. The scanner records absent items, contradictory array/count combinations, inaccessible descriptor arrays, null data pointers, zero lengths, nonzero reserved fields, and repeated ExtTypes within a record. A bounded table tracks duplicate types without storing identities or event payloads. Resource exhaustion or an API/callback failure preserves partial counts and prevents a complete result.

A Process Start Key is only a structural candidate if exactly one type-13 item occurs, its DataSize is eight, its pointer is non-null and readable for eight bytes, and the record is otherwise structurally acceptable. The scalar value is never retained, compared, hashed, or serialized. Absent, duplicate, malformed, or uninspectable key evidence stays UNKNOWN. A candidate does not establish the identity of a process mentioned in event payload data; the scanner never parses UserData and never constructs process or thread generations.

The output is a fresh `scan-<attempt>` directory below the executable directory. The directory is pinned without delete sharing. `STARTED.txt`, `aggregate.json`, and `completion.json` use `CREATE_NEW`; existing attempts and files are never overwritten or adopted. The marker remains as evidence. Empty, truncated, unparsable, missing, or non-complete completion output means partial or unknown. A valid completion also requires successful output flush/close results and native exit code zero. The completion binds the exact aggregate bytes with SHA256 and length. No directory-fsync or power-loss durability guarantee is asserted.

The aggregate records trace open/process/close status, input binding checks, explicit input-handle close status, raw clock information, delivery-order anomalies, buffer counts, header loss counters, documented Lost_Event notifications, output status, and counter conservation. Zero observed loss does not prove capture completeness. Equal-timestamp callback order does not establish causality. The `EVENT_TRACE_LOGFILE.EventsLost` member is labelled unused and is never substituted for a valid loss counter.

The fixed budgets are 16,384 event buckets and 65,536 ExtType/DataSize rows. The tests cover absence, malformed pointers and arrays, duplicates, tuple separation, loss-provider discrimination, timestamp anomalies, budget refusal, identity-value noninterference in serialization, counter conservation, and completion refusal. Actual Windows ETL delivery and real input output behavior remain unvalidated until an independent review and separately authorized saved-file invocation.
