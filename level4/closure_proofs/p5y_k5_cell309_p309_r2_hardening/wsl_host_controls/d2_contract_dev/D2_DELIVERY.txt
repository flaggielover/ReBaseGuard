Delivered library behavior
- Existing strict H4 parser, immutable broker lifecycle, bounded serialized
  in-process dispatch and strict H3 parsing/staging remain unchanged.
- d2_observer.py: H1 request parser and H3->H1 enrollment wrapper. Only challenge
  fields and configured guest/runtime comparison digests are accepted. Caller
  facts, coverage, payload, commands, paths or arbitrary bytes-to-sign fail.
  _fixture_response constructs unsigned message bytes only from fixture-owned
  enrollment/facts. It is not a collector/signing service or a baseline bootstrap.
- d2_signature.py: bounded PUBLIC-number RSA PKCS#1 v1.5/SHA256 reference
  verification. Exact signature width/range and the full DigestInfo/padding are
  checked. No key generation, private key, signing API, subprocess or crypto
  provider is used. Public numbers are2048/3072/4096-bit odd moduli, odd exponent
  3..2^32-1. The domain-separated development public-number fingerprint is NOT
  the old PEM digest, an SPKI pin or a production enrollment format. Reference
  arithmetic and known answers are not production cryptographic review/certification.
- d2_session.py: immutable, bounded one-outstanding-challenge session reducer.
  Synthetic enrollment/host/service/session/baseline bindings are pinned at
  fixture creation. Nonce reuse, stale challenge/sequence/checkpoint, changed
  identity/runtime/policy, missing coverage, busy facts, invalid intervals,
  wrong public pin/signature/peer and transport loss terminate the model.
  Both pre- and post-verification fake times obey the original105s allowance;
  sample intervals remain60..105s. Idle ticks/status cannot renew liveness;
  even requesting a fresh challenge after an expired gap is refused. All fake
  times are bounded exact integer milliseconds in a COMMON SYNTHETIC TIME DOMAIN,
  not measurements or a host/guest clock synchronization claim. Terminal state
  never resumes/rearms. Session records/nonces remain bounded to4096.
- d2_chain.py: composes the session reducer with the unchanged broker reducer.
  Terminal session failure constructs a fixed status/stop-contract stop for its
  PREVIOUSLY ASSOCIATED G using captured synthetic monitor context. H3 bytes
  never become a broker command. Old-G/old-peer checking occurs in the broker;
  failures cannot target a replacement G. No public start, PID/unit selection,
  executor, real manager action or cleanup claim is introduced. Receipt and
  synthetic all-predicate cleanup remain distinct. Restart stays unknown.
