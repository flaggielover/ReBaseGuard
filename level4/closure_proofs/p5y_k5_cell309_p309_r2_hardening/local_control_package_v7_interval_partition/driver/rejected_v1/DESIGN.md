# Saved-input partition driver

This is an additive derivative of the previously reviewed v5 input-integrity wrapper (source SHA-256 `9eb9e1fe69e8b6d148c71714c907d0bccc5198c715ee850681064cdc2fd221b6`). It cannot collect events, install anything, request elevation, launch a VM, sign host facts, issue a grant or admit a host.

Schema 2 adds the interval core to the existing explicit posthoc binding manifest. CSV, decoder summaries, adapter, account utility, interval core and driver hashes are checked while ordinary read handles pin every input and ancestor against normal data-write/delete sharing. Each adapter pass consumes the same verified CSV file handle in full, independently hashes its bytes and checks the decoded/CSwitch row counts. Exactly two completed passes are required. Small sources and summaries execute/read from bounded snapshots. Account and core modules are compiled from those exact snapshots, inserted temporarily for adapter imports, and prior modules restored afterwards. There is no mutable local import lookup for these modules.

For the actual run, the caller will read the driver bytes, verify the explicit SHA-256, then compile/execute those same bytes, with a fixed `__file__`; a matching file on disk is not by itself proof of the source already executing in memory. The driver pins and checks its matching disk copy throughout the run. The ordinary interpreter and standard library remain offline analysis tools, not the private P309 runtime or a complete production software-custody claim.

All claims are posthoc saved-input checks. They do not retroactively bind the original decoder invocation, fix the raw CPU namespace proof, deny every metadata change, or resist a host administrator/kernel adversary. An optional decisions file must be a new distinct path; partial output from a failed audit remains incomplete evidence. Only the final success receipt, after both full passes and rechecks, may describe that audit as completed. Any claimed complete coverage, non-OPEN findings or non-BLOCKED admission is rejected.

Five new synthetic binding methods check poisoned-import isolation/restoration, tampering of each added source, missing second pass, prohibited coverage promotion, and existing/private-output collision. They do not test actual trace semantics. The unchanged historical eleven integrity tests are not repeated. New adapter tests and independent static integration review are separate prerequisites before the actual saved CSV audit. No new host facts, trace, VM, workload or UAC is needed for this offline operation.
