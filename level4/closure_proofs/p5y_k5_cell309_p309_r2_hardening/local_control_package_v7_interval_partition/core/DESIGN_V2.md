# Conservative interval partition v2: bind before clipping

v1 is rejected. Its 11 passing tests encoded incorrect cross-TID and cross-PID reassignment. Original source, tests, design and preparation record are preserved byte-for-byte in rejected_v1/. Their PASS does not validate v2 or actual data.

API: `partition_interval(tid, interval, thread_generations, process_generations, window, *, thread_evidence=None, process_evidence=None)`.

Generation maps retain the v4 shape: `{numeric_id: [(start, end, identity, rundown_bool), ...]}`. Thread identity is PID; process identity is ProcessKey. Evidence maps use `{numeric_id: {row_ordinal: {start_kind, start_anchor, end_kind, end_anchor}}}`. START anchor must equal the row start. RUNDOWN requires the actual observed rundown timestamp inside the row; traceLow is not a birth or presence anchor. END end_anchor must equal the row end; a RUNDOWN end_anchor may be earlier than the v4 synthetic traceHigh, and only proves existence through that actual DCEnd observation. Anchors must satisfy row.start <= start_anchor <= end_anchor <= row.end. SYNTHETIC_HIGH without a real endpoint observation is explicitly rejected as an ownership proof. Missing metadata remains UNKNOWN. The adapter must reconstruct metadata from bound raw lifecycle events, never fabricate START/END labels from tuples alone.

Binding precedes all window clipping. The original CSwitch start must identify exactly one thread row, counting closed endpoints for ambiguity: adjacent generations at the same QPC therefore remain UNKNOWN without event-order evidence. The original start must also be within the thread's actual existence interval. Then bind that thread to one process row at its actual Start/rundown anchor. The entire thread existence interval must fit inside the selected process existence interval. This deliberately conservative full-thread condition can reject valid prefixes if a supplied thread outlives its process; it never reparents a thread after PID reuse. A window that hides a bad birth anchor cannot make the result KNOWN.

After binding, collect intersecting thread/process boundaries and actual existence anchors. Each positive-duration half-open slice is KNOWN only when it is inside the SAME bound thread and process and no other candidate covers the slice. A new TID/ProcessKey can never claim the original CSwitch tail. A later, separately supplied CSwitch interval may bind a later generation. Zero-duration rows contribute boundaries, not ticks. No PID0/TID0/zero-ProcessKey exemption, ThreadEnd extension or timing tolerance exists.

Results retain binding candidates, binding_error, selected original rows, explicit existence proof, per-slice candidates/identity/reason, boundary evidence and conservation totals. Row ordinals are local supplied-list references, not authenticated generation identifiers. KNOWN means conditional on supplied evidence, not host completeness. Caller still proves CSwitch continuity, schema, event loss, actual anchors, identity, same-byte provenance and clock/CPU namespace. Maps are revalidated per call; integration may supply the relevant per-TID/per-PID subsets without changing ordinals, or later review an immutable indexed adapter.

Only small supplied-data tests run with existing Windows Python 3.12.14 as OFFLINE_ANALYSIS_TOOL. No actual saved numeric input is processed. 0.4392592 seconds stays unchanged; no P309 private runtime qualification, threshold change, new host query, UAC, trace, VM, service or workload.
