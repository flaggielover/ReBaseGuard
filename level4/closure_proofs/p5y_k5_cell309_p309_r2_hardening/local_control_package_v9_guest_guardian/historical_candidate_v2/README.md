# v9 native guardian/gate candidate

SOURCE CANDIDATE: not native-compiled, independently passed, installed or approved to execute. The eight retained Python wire/receipt tests do not exercise C, systemd, kernel APIs or OpenSSL. First-candidate bytes/logs are preserved in `rejected_candidate_v1`. The earlier refusal-only source under `intermediate_unconnected` is excluded from builds. Original v1/D2/accepted r2 are unchanged. I1–I7 OPEN; admission BLOCKED.

## Actual source interfaces

The broker owns a lifetime `struct p309_start_control control={0}` and calls `p309_start_fixed_gate(&control,&authority)` once. Cancellation is atomic, irreversible, available before manager Start, and never reset/reused. The factory verifies actual broker PID/start/executable/InvocationID, generates G/challenge inside opaque state, consumes a root-protected local permit, signs and durably saves ROOT_PRESTART, then requires purpose-signed host session and same-transaction ReserveACK BEFORE one StartTransientUnit.

The Start dispatch CAS marks in-flight work. STOP before it prevents Start. STOP after it cannot recall an in-flight syscall: a successful late return yields ECANCELED with retained non-null authority, requests stop via owned killFD and must be reconciled. Unknown manager outcome leaves the blocked gate deadline responsible for no payload; no kill-by-name/adoption/retry occurs. Failed/consumed fences remain.

JobRemoved uses a 16-entry early-event cache, then matches exact canonical job ID/path/unit/result after method reply. Overflow/conflict/duplicate refuses. Before Start, manager UnitPath is checked for fixed fragment and generic/dash-prefix orphan drop-ins. Afterwards actual effective properties are read back: transient/fragment/source/dropins, numeric UID/GID, user/group, exact ExecStart/one argv/no extra execution hooks, restart/kill/delegation/dynamic-user settings, protections/capabilities, stdio and resource limits. Unsupported properties refuse. Concurrent trusted-root installation changes are excluded by the installation transaction contract, not defended against as a malicious-root scenario.

Successful authority retains broker/worker pidfds, original cgroup directory and killFD, RefUnit connection and exclusive root0444 same-build binary record. Independent guardian/gate factories verify that record plus current manager identities. PID1 peer credentials on an activated listener are recognized as socket creation provenance; actual broker identity still comes from manager facts and the completed transaction.

Guardian receives exactly five SCM_RIGHTS FDs with CLOEXEC, rejects ancillary/truncation errors, verifies real ownership, then READY. Broker retains actual guardian pidfd/InvocationID and persists `guardian-ready-v9.claim`. Guardian is a separate unit/cgroup. Broker loss, heartbeat EOF/error/backlog, bad frame, signal, clock failure/reversal, 3-second lease or 120-second development hard bound stop only the held cgroup object. STOP write occurs before nonblocking notification. LOCAL_QUIESCENT is not manager cleanup or formal STOPPED.

Release uses atomic prepare/dispatch states. Duplicate attempts STOP. GateReady, current manager instance, signed host FinalACK and durable consumption must all complete with cancellation rechecks. CAS immediately before nonblocking send is the dispatch boundary: STOP winning earlier prevents RELEASE; later STOP is in-flight and still kills the owned generation. Send success alone is not exec/RUNNING. Same PID/start/Invocation may change from fixed gate to fixed idle only after consumed dispatch; arbitrary executable or replacement process fails.

STOP latches before killFD write or notification, without manager/storage/ACK locks. Retirement requires STOP_REQUESTED, LOCAL_QUIESCENT, manager worker exit/no Job, RETIRING and actual guardian exit/no Job. Errors retain ownership and UNKNOWN. Retirement does not free shared objects/FDs. Owner joins ALL callers before `p309_guardian_destroy_after_join`, then `p309_authority_dispose_after_cleanup`; authority/control must outlive all users. No descriptor ABA or object free occurs in STOP.

## Two-stage host dependency

`anchor_authority.inc` is private to manager_authority.c. It constructs two exact-purpose root proofs from opaque native state: ROOT_PRESTART before worker Start, BLOCKED_INVOCATION only after authenticated actual READY/GateReady/current-manager checks. Private signing is not an exported service/API, cannot select arbitrary paths/keys and only opens already enrolled root0400 `guest-blocked-v10.private.pem`. Derived RSA3072 SPKI must match its installed pin. No key generation, TOFU, arbitrary JSON authority or D2 synthetic provider exists.

`anchor_crypto.c` verifies RSA3072/SHA256/PKCS1v1.5 with exactly 384 signature bytes, using protected root0444 `/etc/rebaseguard-p309/host-anchor-ack-v10.spki.der` and `.spki.sha256`. Pin hashes canonical rsaEncryption SPKI DER. The distinct signed VM session is compared with local G/challenge/boot/approved hashes/own root key pin/host ACK pin. ReserveACK must match that validated context; it cannot supply its own expected fields. FinalACK also binds worker/broker InvocationIDs and SHA256 of the exact canonical blocked proof body, with a strictly later positive Int64 record sequence. Exclusive persistent consumption prevents retry; host independent durable reserve/consume supplies cross-guest rollback protection, never the guest files alone.

`anchor_transport.c` is a fixed protected root0600 `/run/rebaseguard-p309/host-anchor-v10.sock` SOCK_SEQPACKET client: two-second absolute BOOTTIME budget, no retries, no ancillary descriptors/truncation/EOF acceptance. One signed ROOT_PRESTART request yields two ordered frames (signed session, signed ReserveACK) from ONE host reservation. Signed blocked proof yields one FinalACK. Frame is canonical ASCII body plus 384 binary signature bytes. Relay credentials alone do not authorize. Actual host held-VM/H2 factory and independently approved bootstrap/enrollment are hard external dependencies; missing key/relay/context/ACK means no Start/Release. Guest root signature is trusted software evidence, not hardware attestation.

Protected installed hashes are package-v9.sha256, guest-v9.sha256, runtime-v9.sha256, policy-v9.sha256, guest-blocked-v10.spki.sha256 and host ACK key pin: 64 lowercase hex+LF, root0444 under protected `/etc/rebaseguard-p309`. They must come from the approved installer; their existence is not whole-tree verification. Native source does not provision them.

## Fixed objects, limits and remaining work

Worker: p309-dev-owned-check.service. Binaries: fixed /usr/local/libexec/rebaseguard-p309/{control-broker-v9,fixed-gate-v9,idle-owned-v9,guardian-v9}. Gate socket root:p309-runner0660; guardian root:root0600, under root0755 /run/rebaseguard-p309. Root0755 bindings-v9 publishes active-v9.bin root0444. Root0700 /var/lib/rebaseguard-p309-control retains exclusive local permit consumption, signed prestart/context/reserve, READY, blocked-proof and final-consume files. No automatic reset/deletion/rearm.

The local root0600 permit is exactly `IDLE_V9_ONCE\n` + approval SHA/LF + package SHA/LF (143 bytes). It is necessary but insufficient: both host stages are mandatory even for idle. No formal accepted-r2 authority/marker is generated. Fixed idle resource bounds are development-only; they do not substitute for formal workload limits.

Full broker main/admin/H4/signed safety parser and units are the next implementation, not supplied by these libraries alone. Production safety provider is still missing; neither heartbeat nor release may use D2 synthetic facts. Complete monitor/host stop/install/VM factory remains required. Native compile/ABI/property support, socket activation, cancellation ordering, OpenSSL/CNG interoperability and kernel/clock failure cases require independent build/review and separately authorized runtime acceptance. Gate's 10-second setup limit and guardian's 3-second lease may reject slow initialization; no threshold is relaxed to fabricate success. Formal 60-second/5-second suspend/45-second gap semantics remain unchanged.
